# Addressing

Everything in a view has an address, so a paper, a notebook, a chat with an agent or another viewer can point at it.

## Ids and addresses

Ids are local: an id only has to be unique among its siblings. A node's address is the path of ids from the root, the
way an IPv6 address is a path of groups: `/data/p53/features`. `/data/p53/*` names a whole subtree. Nodes made from data
take ids from their keys, such as `/data/1tup/A` for a chain or `/data/globins/rows/HBA_HUMAN` for a row.

A segment can also be a query form, `(kind :key value)`, which selects among what the path so far names. It is the same
grammar meso\* uses:

| Address                                                                                            | Names                                           |
| -------------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| `/data/p53/(range :from 120 :to 130 :numbering uniprot)`                                           | residues 120 to 130 in UniProt numbering        |
| `/data/1tup/A/(at :label 94A :numbering auth)`                                                     | one residue by author number and insertion code |
| `/data/p53/features/(item :type domain)`                                                           | every domain                                    |
| `/data/globins/(rect :rows (rows :from HBA_HUMAN :to HBB_HUMAN) :columns (range :from 30 :to 60))` | a block of an alignment                         |
| `/data/trna/pairs/(rect :a (range :from 10 :to 25) :b (range :from 40 :to 55))`                    | a rectangle of a dot plot                       |
| `/views/main/(viewport :focus /refs/dbd)`                                                          | a view opened on a named region                 |

Rects (two ranges over two axes) can be selected, highlighted, focused and linked just like ranges.

## Your own refs

A `refs` container holds names you define, each pointing at an address: `/refs/dbd` for the DNA-binding domain, say. A
ref works anywhere an address does: in layers, focus, commands, links and other refs. Bookmarks and location sets are
refs. When a node moves or is renamed, everything that names it is rewritten. A ref whose target is gone is reported,
and the rest of the spec still opens.

## What acts on addresses

- **Commands**: focus, reveal, select, highlight, hover, step a snapshot. Every command with a target takes an address,
  so a link, a menu, a key, an agent and a test all drive the view the same way.
- **Links**: an action plus an address, in Mol\*'s link grammar, for example `!seq-focus=/refs/dbd`. One link can carry
  both Mol\*'s and Seq\*'s keys, and each viewer runs the keys it knows.
- **Copy link**: the view gives back the address of whatever is under the pointer or selected, in its shortest stable
  form: a ref if one names it, otherwise ids and forms.

The showcases to come: a text whose links drive a view and a structure; copy link from the view back into text; and one
location addressed in several numberings.
