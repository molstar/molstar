# Composition

A spec is short and declarative, written by people and agents. What the viewer, the data runtimes and other renderers
need is explicit. In between sit three compiled forms, made by pure passes, so each consumer reads one of them.

## One language, four levels

```
spec
├── data        sources, sequences, alignments, maps, annotations
├── views       views → sections → tracks → layers; themes; focus; highlights
├── refs        your names for addresses: bookmarks, regions, sets
└── snapshots   named patches over the base: a story's steps
```

- One language with one version. The levels are containers, so addresses read `/data/p53` or `/views/main`.
- Sublanguages fill slots: queries (a layer's data, a filter, an address's forms), themes and patches.
- **Session is not the spec.** The viewport, the selection, the hover and open panels are transient. Snapshots and refs
  are how a spec names a view state on purpose.

## Three compiled forms

```
spec ─read─▶ checked spec ─resolve─▶ resolved model ─▶ resolved view ─layout─▶ draw lists ─▶ backend
                                                                                   ▲
                                                 data store ◀── runtimes ◀── requests for the regions in view
```

- **Resolved model**: every coordinate system, maps resolved with their paths, each source bound to its runtime, and
  each annotation's fields and access plan.
- **Resolved view**: views, sections, tracks and layers, with themes resolved and fallback chains. It holds no data, no
  pixels and no target, so it is the same for every renderer, and other viewers can read it.
- **Draw lists**: the resolved view laid out for a size, a viewport and a target, from the data store's current entries.

The **data store** sits outside the passes. Visible layers ask for regions, runtimes answer, and entries arrive with
versions. Pending is never drawn as empty. Nothing from the store goes into the spec or the resolved forms.

Every entry of a compiled form is keyed by its address and versioned by its inputs, so a patch recompiles only what it
touched.
