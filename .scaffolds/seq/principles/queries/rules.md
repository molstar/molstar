# Queries and semantics rules {#queries-rules}

Query DSLs over representations, the semantic layer that connects them, and the core concepts and embedded languages they share.

## In brief

**Query DSLs** (§query-languages). Each representation has one or more query languages, and queries are representations too. A shared
core; execution separate from the language; runs take a query context, are cancelable, the work they size is bounded before it starts, and stage async rather than
weave it in. Results are representations; live queries re-evaluate on change. Queries are reachable by command; compiled
forms are derived representations. Dialects are surface syntaxes that lower to a canonical language. Query languages
compose by default.

**Semantic layer** (§semantic-concepts). Concepts say what things are; representations realize concepts; spaces say how a thing is
addressed. A locator is a semantic reference as data, and everything that points at something uses locators. Mappings
connect representations (with declared fidelity); a router composes them; spaces and most mappings are declared in a
small language (renames, offsets, lookup tables, ranges), not coded (§addressing-language); navigation is by meaning and bounded.
Quantities carry dimensions and units. The layer is itself data, queryable and reachable by command. Instances
realize concepts; concept commands (`task.complete`) lower to the representation's operations; authored is content, inferred is an
attachment (§concept-instances).

**Core concepts and embedding** (§core-concepts). Common types (quantity, vectors, box, interval, transform, time, signal, table,
tensor) are defined once with their generic operations; DSLs can embed each other, recursion bounded by data.
Document concepts (task, decision, question, mention, reference, thread, message) belong to the document module.

Patterns: §query-dsls, §semantic-layer, §core-concepts-and-embedding, meso's `tables` (not adopted here), meso's `documents` (not adopted here) (all sketches).

## Query DSLs over representations {#query-languages}

Representations are queried with declarative languages in the spirit of MolQL for molecular structure; the same idea applies to UI state, DB schemas, scenes and the rest. → [§query-dsls](sketch-patterns/query-dsls/README.md)

1. **Each representation is queryable by one or more query languages**, {#queryable-representations} owned by the module that owns the representation (§representation-modules). Contexts that need different *semantics* get different languages: selection (which nodes), structural pattern matching, navigation, aggregation and statistics. Each language has its own canonical form, engine and conformance suite, declares what its results are (locators, values, tables), and may embed the others (§embedded-dsls), e.g. an aggregation over a selection. Add a language only for new semantics; a new syntax for existing semantics is a dialect (§dialects-lower).
2. **Queries are representations too**: {#queries-are-representations} expression trees in the same spelling (S-expressions by default), so they can be stored, diffed, sent to a remote engine, generated by agents and logged.
3. **A shared query core** {#shared-query-core} (`repr-core/query`) provides the language machinery: function registry, compilation, composition (`and`/`or`/`not`, tree navigation, selection). Domain modules **register domain functions** (e.g. `residue-name`, `route-matches`, `column-type`) on top, and reuse the generic ones defined on core concepts (`within`, `during`; §generic-operations); they do not reimplement the engine.
4. **Execution is separate from the language.** {#execution-separate} An engine runs a query over a representation; it may scan, use indexes, or push the query to a remote store or GPU (via ports, §compose-through-ports). The semantics are fixed by the language and checked by one conformance suite (§conformance-suites), whatever engine runs it.
5. **Runs take a query context**, {#query-context} created in the composition root (§composition-root): shared caches (compiled queries; derived indexes keyed by the immutable snapshot they were built from), cancellation, limits and deadlines, tracing. The context changes cost and bounds, never results, and lets callers apply different policy (bounded for agents).
6. **Async is staged, not woven in.** {#staged-async} The language and evaluator are synchronous and pure over one immutable snapshot. Queries that need external data (remote stores, lazily loaded data, similarity services) use *staged* functions: an async `prepare` step (batched, cached per snapshot, cancelable) yields a synchronous predicate. Engines expose the three surfaces (`run`, `runAsync`, `stream`; §api-boundaries).
7. **Queries are cancelable**: {#cancelable-queries} every run honors the context's signal, deadlines and limits; async calls forward the signal to ports; streams cancel on unsubscribe; commands pass their signal through; aborted runs leave no partial results or cache entries.
8. **Results are representations**: {#results-are-representations} selections of locators (§locators, §composable-queries), values, or subtrees, which can be streamed (§streamable).
9. **Live queries** {#live-queries} are streaming queries: results update as state changes; a new snapshot cancels an in-flight async run and stale results are dropped.
10. **Reachable by command (§command-reachable)**: {#queries-by-command} `state.query` (read-only) takes a query, optionally naming its language or dialect, and returns results, so agents and UI inspect state with the same languages.
11. **Compiled forms are derived representations (meso's `derived-forms` (not adopted here)).** {#compiled-queries-derived} A query's normalized form, plan and compiled predicate are keyed by the query's hash and the snapshot, cached in the query context, inspectable (`derive.explain`), and map errors back to the query as written.
12. **Dialects are surface syntaxes that lower to a canonical language.** {#dialects-lower} A compact notation for a search box (`A:42-45 ALA`), a domain's traditional syntax, or a verbose form for agents parses to its own tree and is lowered to the canonical query by a pass (meso's `pure-passes` (not adopted here)) with provenance, so errors point at what was written (meso's `provenance` (not adopted here)). Engines, caches and conformance see only canonical queries; storage and the wire carry the canonical form, or the dialect text plus its dialect id when the author's spelling must be kept. Each dialect ships a lowering suite (written form → expected canonical form) and, where feasible, a printer back into its notation.
13. **Query languages are composable by default** {#composable-queries} (in the spirit of MolQL's generators, modifiers and filters). A query denotes a value of one type (for selection languages, a *selection*: a set of groups of nodes), and the language is built from a few roles: **generators** create selections from the representation, **modifiers** transform each group (expand to whole residues, add surroundings), **filters** keep or drop groups, **combinators** merge selections (union, intersect, subtract); plain predicates are the tests used inside generators and filters. Every stage takes and returns the same type, so queries chain and nest (a modifier applies per group and the results are flattened: monadic composition), sub-queries are reusable values, and agents build queries step by step. Languages whose semantics do not fit (an aggregation that folds a selection into values, a pattern language with its own algebra) may opt out; they say so, and still take selections as inputs where that makes sense.
14. **Work is bounded before it starts.** {#queries-bounded-work} Moved to the representations rules (§bounded-work), which cover queries and every other pass.

## Semantic layer: concepts, spaces and mappings {#semantic-concepts}

Above the representations and DSLs (document tree, UI, scene, molecular structure, DB schema, text, data blobs) sits a lightweight **semantic layer**: a shared description of *what things mean* and *how to get from one representation of a thing to another*. It is how people, tools and agents navigate across the DSLs without knowing each one's internals. Keep it light: declare what is useful, skip the rest. → [§semantic-layer](sketch-patterns/semantic-layer/README.md)

1. **Concepts say what things are.** {#concepts} A concept has an id (`Residue`, `Shape`, `Selection`), a description, optional `isa`, typed attributes (with units where they are quantities), and relations to other concepts (`part-of`, `refers-to`, `derived-from`, `depicts`). Concepts are data (§declarative-representations), declared by the module that owns the domain (§representation-modules); shared ones live in the core (§core-concepts), products extend them.
2. **Representations realize concepts.** {#realized-concepts} Each module's vocabulary states which concepts its node kinds and attributes realize (`mesh` realizes `Shape`; the molecular `residue` node realizes `Residue`; a DB `column` realizes `Field`). This bridges a DSL's local terms and shared meaning.
3. **Spaces say how a thing is addressed.** {#spaces} A *space* is an addressing scheme within a representation: entity ids, paths, indices, text ranges, screen pixels, world coordinates. Each is declared once (coordinate schema, kind, stability: stable / positional / ephemeral; for spatial spaces dimensions, units, handedness, parent). A bare coordinate or index crossing a module boundary is a bug: it travels as a locator.
4. **A locator is a semantic reference, as data**: {#locators} `(at <space> <coordinates> [(is <Concept>)] [(anchor ...)])`. Printable, hashable (§merkle-hashing), streamable, writable by agents. Prefer stable coordinates (entity ids); positional ones carry an anchor and go stale visibly.
5. **Mappings connect representations.** {#mappings} A mapping translates locators between spaces and/or concepts (`screen → world → doc entity → molecular residue → text range`). It lives in a runtime behind a port, registered in the composition root (§composition-root), is sync or async (§api-boundaries), cancelable and cached, and never lives in the state layer. Mappings declare their **fidelity** (`exact | approximate | lossy`, as an upper bound up front and per result), may be one-to-many or empty, and a chain is as good as its weakest hop.
6. **A router composes mappings.** {#mapping-router} Adding one mapping connects everything it touches to everything already connected. Failure is a coded error (`locator.no_path`, `locator.stale`, `locator.unresolved`; §stable-error-codes) with a hint listing what is reachable.
7. **Navigate by meaning.** {#navigate-by-meaning} Concept-level queries fan out over every representation that realizes the concept and return locators (`all Residue where name = ALA`, in the document, the structure and the sequence view); relation traversal follows `part-of`/`refers-to`/`depicts` across representations. Per-representation DSLs (§query-languages) remain the precise tools; the semantic layer routes to them.
8. **Quantities carry dimensions and units** {#units-and-dimensions} so values convert correctly between representations (Å ↔ nm ↔ m, px ↔ world); conversions are exact value functions in the core (§core-concepts), used by spatial mappings.
9. **The layer itself is data, queryable and reachable by command.** {#layer-is-data} The registry of concepts, realizations, spaces and mappings is a representation, queried with the same DSL and exposed through commands (`sem.concepts`, `sem.path`, `sem.convert`, `sem.select`; §command-reachable). It is part of the machine-readable spec (§spec-folders): `_spec/` links to it, and the gate checks the links resolve (§mechanical-drift-checks).
10. **Everything that points at something uses locators**: {#locators-everywhere} query results, command arguments, selections shared between views (select in 3D, highlight in the sequence and tree views), error positions (§namespaced-codes), spec-to-code references (§spec-folders), data ranges (meso's `data-referencing` (not adopted here)), presence cursors (§live-uncommitted-sharing).
11. **Spatial transforms are a special case**: {#spatial-transforms} mappings over a space graph with matrices, units and handedness declared on the spaces; hot-path transforms write into caller-provided buffers (§performance).
12. **Navigation is bounded.** {#bounded-navigation} Chain length, fan-out and time come from the query context (§query-context), so concept queries and conversions are cancelable and cannot explode.
13. **Addressing schemes and their translations are a language.** {#addressing-language} Spaces are declared in a small space language (the coordinate key: fields, types, which fields form ranges; the concept addressed; stability), and most mappings are declared in a mapping language instead of coded: field renames, arithmetic offsets, lookups through a correspondence table (a `Table`, meso's `collections` (not adopted here)) carried by or derived from the data, range alignments (segments), composition and inverses. One domain usually has several spaces for the same things (two numbering schemes of the same residues, a sequence position, a position in an external database); each is a first-class space, and the translations between them are declared mappings, so the router composes them (§mapping-router), fidelity is known, and agents never do numbering arithmetic themselves. Declared mappings are range-aware (a range may map to several ranges), invertible when declared bijective, compiled to runtime mappings (§mappings) and tested by round trip. Hand-written mappings remain for what cannot be declared (picking, rendering, learned or heuristic matches).
14. **Instances realize concepts, and say who asserted them.** {#concept-instances} A node realizes a concept by its kind (§realized-concepts); **concept commands** (`task.complete`, `decision.settle`) are declared with the concept and lower to the representation's operations. What a person authored (a task, its condition, its assignee) is content; what an agent inferred about it (that a message satisfies it, a summary) is an attachment (meso's `attachments` (not adopted here)) until someone commits it as content. → [meso's `documents` (not adopted here)](../../../principles/representations/README.md)

## Core concepts and embedded languages {#core-concepts}

The shared vocabulary every domain builds on, and how DSLs compose. → [§core-concepts-and-embedding](sketch-patterns/core-concepts-and-embedding/README.md)

1. **Core concepts for common data types.** {#core-data-types} A small core module next to `repr-core` defines the building blocks every domain reuses, each as a concept (§concepts) with a representation (§declarative-representations), query functions, spaces and mappings: **scalars and quantities** (value + unit), **vectors** in 1D/2D/3D(/4D), **intervals, boxes and regions**, **transforms**, **time** (instants, durations, intervals, sampled series), **tables** (dataframes: records of one schema in row or column layout, with filter, project, sort, group and join, meso's `collections` (not adopted here)), **tensors** (shape + dtype; the bytes are referenced data, meso's `data-referencing` (not adopted here)), **ids** and **text spans**. Higher-level concepts are built from these: a residue has a `Vec3` position in length units, a shape has a `Box`, an animation is a `Signal<Vec3>` over `Time`. Concepts every product with documents shares (task, question, decision, mention, reference, thread, message) are owned by the document module, not this core set (§concept-instances).
2. **DSLs can embed each other, including mutually recursively.** {#embedded-dsls} A language declares *slots* where other languages or core forms may appear (`(style (target <mol-query>) (paint <expr>))`, a query whose argument is a time expression). Embedded languages are referenced **by id and resolved late** through a language registry built in the composition root, so languages can refer to each other (A embeds B embeds A) while **modules stay acyclic** (§common-vs-product): each language module depends on the core and registers itself; the cycle exists only in data. The tree is uniform (§declarative-representations), so parsing, printing, hashing and streaming are unaffected; validation, evaluation and queries dispatch on the slot's language.
3. **Generic operations are defined once, on core types**: {#generic-operations} spatial (`within`, `inside`, `intersects`), temporal (`before`, `during`), unit conversion and interpolation. A domain supplies only how to read a position or time from its nodes.
4. **Recursion is bounded by data.** {#bounded-recursion} Trees are finite, so syntactic embedding always terminates; evaluation depth is limited by the query context (§query-context); cycles are checked only for references (named definitions, data refs), not for syntax.
