# Query DSLs over representations {#query-dsls}

- **Implementations:** [TypeScript](typescript.md)

Rules §query-languages, §embedded-dsls: every representation is queried by a declarative language (MolQL-style); the core (`repr-core/query`) is shared, domains add functions, engines differ only in cost; queries and results are representations.

## Problem

Without a shared query language each representation grows its own finders and filters: the UI, commands and agents look
things up differently, an in-memory path and a remote one disagree, and a lookup cannot be printed, stored, sent or
checked. Long or remote lookups then block or cannot be cancelled, and caching is improvised per call site.

## Shape

A query is a `Node` (§representations): it can be printed, stored, sent, diffed and generated by an agent. Names of tags
and attributes are symbols (strings are accepted); values are compared structurally (by value hash; `0` and `-0` differ).

```
(select (and (tag mesh) (attr material "steel")))                          ; UI/scene state
(select (and (tag residue) (attr name "ALA") (within 5 (tag ligand))))      ; molecular (within: core spatial fn, §core-concepts-and-embedding)
(select (and (tag column) (attr type uuid) (not (attr nullable true))))     ; DB schema
```

- **`QueryLang`**: an id and a table of named functions. `register(name, compiler)`; `compile(query) -> compiled`. A
  compiled query is a *predicate* `(node, path, eval) -> bool`, or *staged*: `prepare(eval) -> predicate`, async, run
  once before evaluation. A function compiler receives its arguments, the compiler (for sub-queries) and the
  `LanguageRegistry` (to compile an argument in another language, late-bound by id, §core-concepts-and-embedding).
- **Core functions** every language has: `and`, `or`, `not`, `tag`, `attr`, `has-child`. A domain adds functions, not an
  engine: the molecular language is core + spatial (§core-concepts-and-embedding) + `residue-name`.
- **Selections** (§composable-queries), MolQL's shape: a query denotes a `Selection` (groups of node paths; a residue is
  the paths of its atoms), and every operator (`SelOp`) takes and returns selections, so queries chain and nest, every
  sub-query is a reusable value, and an agent can build a query one stage at a time and inspect each stage.

  | Role | Core operators | Does |
  |---|---|---|
  | generator | `(atoms <pred> [level])` | one walk; groups matches by an ancestor level, or one group per node |
  | modifier | `(expand <sel> <level>)` | applied per group, results flattened (a monadic bind) |
  | filter | `(pick <sel> <test>)`, `(within <sel> r <sel>)` | keeps groups that pass a group-level test |
  | combinator | `(union ...)`, `(intersect ...)` | several selections to one |

  ```
  (union
    (expand (atoms (residue-name HIS) residue) chain)                  ; generator -> modifier
    (within (atoms (tag water) residue) 3.5 (atoms (tag ligand))))     ; filter by relation to another selection
  ```
  `(select p)` is sugar for `(atoms p)`; an engine run returns the flattened selection (all paths), and selection-aware
  callers keep the groups. Opting out is explicit: `mol.measure` folds a selection into values (`count`, `rmsd`) and ends
  a pipeline; it still takes selections as input (a `query` slot).
- **Languages and dialects** (§queryable-representations, §dialects-lower): a representation may have several languages
  (different semantics; the first is its selection language) and several `Dialect`s (another syntax for one language).
  ```
  molecular structure
    mol.select    which atoms/residues        (select (and (chain A) (residue-range 42 45) (residue-name ALA)))
    mol.pattern   structural motif matching   (motif (helix) (followed-by (sheet)))
    mol.measure   aggregation and statistics  (count (query mol.select (select (residue-name ALA))))   ; embeds a selection
    dialect mol.short -> mol.select           A:42-45 ALA
  ```
  A `Dialect` has `id`, `lowersTo` (a language id), `parse(text) -> tree` (coded errors with text positions), `lower` (a
  pass to the canonical query, with a source map back to the text) and optionally `print(canonical) -> text`.
  `resolveQuery(langs, repr, text, id?) -> {lang, canonical, sourceMap?, diagnostics?, repairs}` is the one entry point
  for every caller (search box, agents, commands); without a dialect, the text is read leniently (§parser-repairs-slips)
  and, without an id, the selection language is used. Languages other than selection (measure, pattern) keep the same
  context, cancellation and surfaces but return their own result type.
- **`QueryContext`**: everything a run needs besides data and query, created in the composition root and passed down
  (§dependencies-passed-in): `cache`, `signal`, `limits` (`maxResults`, `deadlineMs`, `maxDepth`), `trace`, `derived`.
  Policy differs per caller (a trusted UI context unbounded, an agent context with `maxResults 1000`, `deadlineMs 200`)
  without touching the engine.
- **`QueryCache`**: compiled queries keyed by language id + printed query (bounded in practice); `forRoot(root, key,
  build)` memoizes per snapshot (indexes, prepared data). Safe because snapshots are immutable with structural sharing:
  a changed state is a new root. Atoms are not cached by identity.
- **`QueryEngine`**, three surfaces with one semantics:

  | Surface | Use | Cancel |
  |---|---|---|
  | `run(root, q, ctx)` | in-memory, nothing staged | not preemptible; bounded by limits; checks the signal while walking |
  | `runAsync(root, q, ctx)` | staged queries, remote engines, chunked runs | abort the signal: rejects with `query.cancelled` |
  | `stream(root, q, ctx)` | progressive or batched results | unsubscribe or abort |

  The scan engine walks every node. An indexed engine builds a tag index per snapshot and tests only candidates, through
  the same limit and signal checks. Remote/GPU engines send the query as-is (pushdown) and forward signal and limits.
- **Async in queries**: a function that needs external data (e.g. `(similar-to "text" k)` over an embeddings port)
  compiles to a staged value whose `prepare` fetches once, batched and cancelable, and returns a plain predicate.
- **Live queries** (§live-queries): `observeQuery(state, engine, q, ctx)` runs on the current root, then on each change.
- **By command** (§command-reachable, §queries-by-command): `state.query {query, lang?, limit?} -> {matches (path,
  node), normalized, repairs}`, e.g. `state.query {"query": "(select (tag mesh))"}`; the agent uses the DSL the UI uses.
  Where nodes have ids, results are locators (§semantic-layer) instead of paths.
- **Errors** (`query.*`): `not_a_query`, `unknown_function`, `bad_argument`, `expected_select`, `needs_async`,
  `cancelled`, `deadline_exceeded` (retryable), `limit_exceeded`.

## Invariants

- The context changes cost and bounds, never results; there is no default context.
- Every engine and every surface returns what the scan engine returns for the same query and snapshot.
- Evaluation is synchronous and pure over one immutable snapshot; async work happens only in `prepare`. A whole run,
  staged parts included, sees one root, also across awaits.
- A combinator over a staged child is staged, and independent `prepare`s run in parallel. `run` on a staged query fails
  with `query.needs_async`.
- A walk checks the signal before starting and about every 1024 nodes, and enforces the deadline; more than
  `maxResults` matches is the error `query.limit_exceeded`, never a silent truncation.
- Nothing partial is cached or emitted: failed or aborted fetches leave no cache entry.
- Every async port call either forwards the caller's signal or is a shared fetch (keyed per snapshot and all arguments)
  that callers stop awaiting on abort; one caller aborting does not cancel the others.
- A live query: a new snapshot cancels the in-flight run, superseded results are dropped, nothing is emitted after
  teardown. Unsubscribing a stream stops it and aborts its port calls; a cancelled command cancels its query.
- Anything potentially long runs through `runAsync` (chunked), which also keeps the main thread responsive
  (§responsive-ui).
- Registering a function name twice in one language is a programmer error. An unknown function fails with
  `query.unknown_function` and the known names in the hint.
- A dialect is parsed and lowered, never executed; the canonical form is what is stored and sent (the dialect text, with
  its id, only when the author's spelling matters). A new language only for new semantics; a new syntax is a dialect.
- A caller may lower the policy's `maxResults`, never raise it.

## Conformance cases

- Tree `(scene (mesh "a") (cam))`, query `(select (tag mesh))` → paths `[[1]]`.
- The same cases through `run`, `runAsync` and `stream` → equal results.
- A query naming an unregistered function → `query.unknown_function`, known names in the hint.
- A matching query with `limits.maxResults 0` → `query.limit_exceeded`.
- Abort during `runAsync` → rejects with `query.cancelled`, port calls aborted, cache unchanged.
- A staged query → the same result as its pre-resolved equivalent.
- Generated trees and queries → every engine equals the scan engine (property).
- Generated queries → `parse(print(q))` equals `q`.
- Selection laws on generated selections: chained modifiers are associative; `(pick s true)` equals `s`; `union` is
  commutative (as a set of groups; order differs) and idempotent; a generator equals the union of its groups.
- Each dialect: written form → expected canonical form, and errors point into the written text. To be decided: the
  cases per dialect (e.g. whether `A:42-45 ALA` lowers to exactly the `mol.select` form above).
- To be decided: cases for `query.not_a_query` and `query.expected_select`, and per-domain suites (e.g. molecular
  function semantics) on the same engines.

## Open

- The predicate `within` (`(within r <pred>)`, §core-concepts-and-embedding) and the selection filter `within`
  (`(within <sel> r <sel>)`) share a name; whether the argument position disambiguates, or one is renamed, is not settled.
- `limits.maxDepth` is on the context, but the evaluator does not read it; where depth is counted is open in
  §core-concepts-and-embedding.
