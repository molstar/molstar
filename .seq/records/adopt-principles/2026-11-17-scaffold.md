# adopt-principles: the .seq scaffold and packages/seq (2026-11-17)

## Asked

The author asked for `packages/seq`, a new implementation of Seq\* drawn from the previous implementation, meso\*'s
language lessons, the JBrowse reply and `@molstar/core/reactive` with `@molstar/ui` ("no more rxjs"). `.seq` was to be
bootstrapped from the oz principles as a temporary scaffold that code never cites. The first step was to unpack the
request and plan the first steps; then the scaffold: the package, its Storybook, and docs on how it will work.

## Decided

- Format: "yes, let's keep using JSON with s expression printing for easier inspection." ([design/format.md](../../design/format.md))
- Sources: "a single protocol … define a source in a format which an application provides a "runtime" for … we
  convert other formats onto it." ([design/sources.md](../../design/sources.md))
- Accepted as recommended ("others as recommended"): the `seqx` package names, the scaffold in `.seq/`, the header,
  the modules, and which reply proposals to take now ([sources/author](../../sources/author/README.md)).
- Recommended, still to be confirmed: the root nouns ([design/building-blocks.md](../../design/building-blocks.md),
  Provisional).

## Learned

- The package's checks cannot read a package that shares its folder with the instance. meso\* shares them and runs
  its own checker; here the package sits apart, in `.seq/oz/`.
- meso\*'s queries and agent-interface modules cite about 19 ids of its larger representations module, which oz lacks.
  Taken as written, they need those ids reworded or the module brought in.
