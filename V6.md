# Mol* v6

Mol* v6 modernizes the library's package structure, distribution, and plugin composition so applications can use the
parts they need with clearer dependencies and less setup.

## Goals

- **Modular packages:** separate core utilities, IO, molecular models, graphics, plugin runtime, UI, headless support,
  and MolViewSpec into packages with explicit ownership and dependencies. Extensions, apps, examples, CLIs, servers, and
  browser distributions have their own workspace locations. Public packages share one release version.
- **Direct ESM consumption:** publish JavaScript modules and TypeScript declarations for Node and browser consumers,
  including a browser-ready distribution that can be used without a consumer build step. Keep source entry points for
  bundlers.
- **Explicit plugin composition:** let applications choose formats, representations, themes, transforms, and behaviors
  through explicit registry entries in the plugin spec. Provide full default configurations through explicit entry
  points and make smaller application bundles practical.
- **A rendering-backend boundary:** separate GPU resources, scenes, passes, and readback from the rest of the library
  while retaining WebGL behavior. This prepares a path to WebGPU and offline rendering; complete WebGPU and Blender
  implementations are later work.
- **Simpler development and reliable releases:** use shared workspace tooling, app-owned builds, and consumer smoke
  checks for published artifacts. Use Biome for linting and formatting, native TypeScript 7 for compilation, and track
  API changes and migration work explicitly.

## Current progress

The current implementation establishes the pnpm workspace, package layout, ESM exports, app tooling, browser
distribution, Biome linting, and repository-wide Biome/Prettier formatting with two-space source indentation.
Compilation uses native TypeScript 7, and CI enforces formatting. Plugin composition is implemented and verified,
including empty registries, `spec.registry`, explicit default specs, transformer/catalog splitting, and the slim-plugin
example. Alex owns the rendering-backend workstream. Remaining architecture, compatibility, and release work is tracked
below.

MolQL builder exposure and standalone validation are currently being designed. The proposed validation pass uses symbol
and argument-definition tables without loading the molecular query runtime. Current `mvs-validate` still checks only
expression shape. Full WebGPU/Blender integration is later work; fast types and isolated declarations are deferred to
consideration for v7.
